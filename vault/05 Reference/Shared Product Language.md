# Shared Product Language

Review date: 2026-05-16

Use these terms consistently in docs, vault notes, and UI copy.

| Term | Meaning |
| --- | --- |
| Today | Daily command center. It answers: what should I do now? |
| Focus | Execution mode for one block. It protects traction. |
| Activity | Non-goal wellbeing or recovery session type. |
| Weekly | Planning surface for capacity, allocation, rollover, and weekly pact. |
| Review | Learning surface for planned vs actual, friction, area balance, and next adjustment. |
| North Star | Read-first direction: identity, season focus, 90-day outcomes, priorities. |
| Areas | Life and career balance scorecard. |
| Goals | Outcomes and next actions. Not a generic task dump. |
| Coach | Contextual assistant that suggests, never judges or commands, with local fallback when HF is unavailable. |
| Brain | Local memory layer for questionnaires, profile synthesis, and Obsidian sync. |
| Research | Search memory and read/save flow for sourced findings. |
| Traction | Intended action. |
| Distraction | Something that pulls away from intended traction. |
| Pact | Pre-decided rule that protects a block, day, or week. |

## Naming Rule

Use `Review` in product language. The old `History` label should only appear when referring to legacy route or migration details.

## Area Categories

Keep top-level categories stable:

- Career
- Learning
- Health
- Money
- Relationships
- Personal Systems

Use tags for subtopics such as `ai-agents`, `backend`, `portfolio`, `client-work`, or `job-search`.

## Tone Rule

Kairos should sound direct, calm, and non-judgmental.

Use:

- What pulled you away?
- What should change next time?
- Start small.
- Adjust the system.

Avoid:

- Failed.
- Bad day.
- You are behind.
- Catch up.
